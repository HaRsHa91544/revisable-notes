# Branching — First Principles Notes

---

# 1. The Engineering Problem

So far, every program executes like this:

```text
Instruction 100
      ↓
Instruction 101
      ↓
Instruction 102
      ↓
Instruction 103
```

Why?

Because after every instruction:

```text
PC ← PC + 1
```

The Program Counter always points to the **next sequential instruction**.

This is called **Straight-Line Execution**.

---

# 2. Why Straight-Line Execution Is Not Enough

Real programs make decisions.

Example:

```c
if (marks >= 35)
    print("PASS");
else
    print("FAIL");
```

Suppose:

```text
marks = 80
```

Should the CPU execute both?

```text
print("PASS")
print("FAIL")
```

❌ No.

It should execute only:

```text
print("PASS")
```

The CPU must **skip** some instructions.

---

# 3. The Question Engineers Asked

The Program Counter always performs:

```text
PC ← PC + 1
```

How can the CPU:

* Skip instructions?
* Jump to another part of the program?
* Execute only one path?

---

# 4. The First Idea

One possibility:

```text
PC ← PC + 2
```

Works for one program.

But another program may require:

```text
Skip 5 instructions
```

or

```text
Skip 100 instructions
```

The CPU cannot guess how many instructions to skip.

---

# 5. The Better Solution

Instead of saying:

> Skip 20 instructions

Tell the CPU:

> Go directly to instruction 250.

So instead of:

```text
PC ← PC + 1
```

the CPU performs:

```text
PC ← 250
```

The next fetch becomes:

```text
Instruction 250
```

The CPU never executes the skipped instructions.

---

# 6. Important Insight

The CPU does **not** skip instructions one by one.

It simply changes the Program Counter.

Example:

Current:

```text
PC = 100
```

Normally:

```text
PC ← 101
```

Branch:

```text
PC ← 900
```

The next instruction fetched is:

```text
Instruction 900
```

Everything between 101 and 899 is ignored.

---

# 7. Who Makes This Decision?

## Program Counter?

No.

The PC only stores an address.

---

## ALU?

No.

The ALU performs arithmetic and updates condition codes.

Its work ends there.

---

## Control Unit?

✅ Yes.

The Control Unit has access to:

* Instruction Register (IR)
* Program Counter (PC)
* Condition Codes (Z, N, C, V)

It decides whether to continue normally or branch.

---

# 8. Decision Process

Suppose the current instruction is:

```assembly
BEQ 900
```

The Control Unit reads:

```text
Instruction = BEQ 900
```

Then checks:

```text
Zero Flag (Z)
```

If:

```text
Z = 1
```

Then:

```text
PC ← 900
```

Otherwise:

```text
PC ← PC + 1
```

---

# 9. Complete Branch Flow

```text
        Fetch
          │
          ▼
     Instruction Register
          │
          ▼
      Control Unit
          │
          ▼
     Decode Instruction
          │
          ▼
Is this a Branch Instruction?
       │             │
      No            Yes
       │             │
       ▼             ▼
PC ← PC+1     Check Condition Flags
                    │
             ┌──────┴──────┐
             │             │
        Condition True   Condition False
             │             │
             ▼             ▼
        PC ← Target     PC ← PC+1
```

---

# 10. Real-Life Analogy

Imagine reading a book.

Normally:

```text
Page 10

↓

Page 11

↓

Page 12
```

Now page 10 says:

> "If you chose the red door, turn to page 85."

Do you read pages 11–84?

❌ No.

You immediately go to:

```text
Page 85
```

Changing the page number is exactly like changing the **Program Counter**.

---

# 11. Official Definition

**Branching** is the process of changing the normal sequential execution of a program by loading a new address into the **Program Counter (PC)**. The decision to branch may be unconditional or based on condition codes generated by previous instructions.

---

# 12. Types of Branching

### 1. Unconditional Branch

Always jump.

```assembly
JMP 500
```

Execution:

```text
PC ← 500
```

No condition is checked.

---

### 2. Conditional Branch

Jump only if a condition is true.

Example:

```assembly
BEQ 500
```

Meaning:

```text
If Z = 1

↓

PC ← 500

Else

↓

PC ← PC + 1
```

---

# 13. Complete Instruction Execution Cycle

```text
Program Counter (PC)
        │
        ▼
Fetch Instruction
        │
        ▼
Instruction Register (IR)
        │
        ▼
Control Unit Decodes
        │
        ▼
ALU Executes
        │
        ▼
Update Flags (Z, N, C, V)
        │
        ▼
Control Unit Checks Flags
        │
        ▼
Update PC
        │
        ├───────────────┐
        │               │
        ▼               ▼
PC ← PC+1        PC ← Target Address
        │
        ▼
Fetch Next Instruction
```

# 17. Memory Hook

> **The Program Counter is like a bookmark in a book.**
>
> * **Normal execution:** Move to the next page (`PC ← PC + 1`).
> * **Branching:** Jump directly to another page (`PC ← Target Address`).
>
> The **ALU** produces the conditions (**Z, N, C, V**), and the **Control Unit** uses those conditions to decide whether to move the bookmark normally or jump to a different location.
